# AWS S3 setup — Upload service, version 1

Story `MVP1-E2-01`. The one-time setup in the AWS console for the private bucket the Upload service stores files in. Nothing here is code. Do it after the AWS account exists (`docs/infra/cognito.md`, Part 0).

| | |
|---|---|
| Region | **US East (N. Virginia), `us-east-1`**, the same as Cognito |
| Bucket | `01scale-uploads` (bucket names are global; if taken, add a suffix and update `UPLOAD_BUCKET`) |
| Time | About 20 minutes |

> Written from knowledge of the AWS console, not run against a live account. If a screen does not match, note the difference here.

## Part 1 — Create the bucket

1. Open **S3** → **Create bucket**. Region `us-east-1`, name `01scale-uploads`.
2. **Object Ownership**: ACLs disabled (bucket owner enforced).
3. **Block Public Access**: keep **all four** boxes ticked.
4. **Bucket Versioning**: disabled. A deleted file must really be gone.
5. **Default encryption**: server-side encryption with Amazon S3 managed keys (**SSE-S3**).
6. Create the bucket.

## Part 2 — Delete files after 30 days

**Management** → **Create lifecycle rule**: name `delete-after-30-days`, apply to all objects, action **Expire current versions of objects** after **30** days. The Upload service marks files `expired` on the same schedule.

## Part 3 — Let browsers upload and read (CORS)

**Permissions** → **Cross-origin resource sharing (CORS)** → Edit, and paste:

```json
[
  {
    "AllowedOrigins": ["https://01scale.com", "http://localhost:3000"],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["Content-Type", "Content-Length"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

Only these two origins can use the links in a browser. The links themselves still need a valid signature.

## Part 4 — Credentials the Upload service uses

1. **IAM** → **Policies** → **Create policy** → JSON, and paste (keep the bucket name in step with Part 1):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "UploadServiceObjects",
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::01scale-uploads/users/*"
    }
  ]
}
```

   Name it `01scale-upload-service`. `s3:HeadObject` is not a separate permission: checking that an object exists is allowed by `s3:GetObject`.
2. **IAM** → **Users** → **Create user** `01scale-upload-service`, with **no** console access. Attach the policy above and nothing else.
3. Open the user → **Security credentials** → **Create access key** → "Application running outside AWS". Copy the key ID and secret into the Upload service's environment variables on Vercel (`UPLOAD_AWS_ACCESS_KEY_ID`, `UPLOAD_AWS_SECRET_ACCESS_KEY`). **Never paste them into a chat, an issue, a pull request or a file in the repository.**

## Check it works

- **Permissions** shows "Bucket and objects not public".
- Uploading a file in the console and opening its **Object URL** in a private browser window shows **AccessDenied**: the bucket is private.
- The lifecycle rule is listed under **Management**.

## Settings summary (for rebuilding)

| Area | Setting |
|---|---|
| Region | `us-east-1` |
| Public access | All blocked |
| Versioning | Off |
| Encryption | SSE-S3 |
| Lifecycle | Expire objects after 30 days |
| CORS | PUT and GET from 01scale.com and localhost:3000 |
| Service credentials | IAM user with Put, Get, Delete on `users/*` only |
